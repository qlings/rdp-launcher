# 开发过程与踩坑

> 换机器继续改之前先看这份。里面每个坑都真踩过，重复踩一遍要花几个小时。

## 〇、v2 改造（2026-11-21）

这一版在原启动器上加了设置、多分组、盘符枚举、声音、序号、单 exe 存储、双击连接和图标。
下面几条是新增的、最有价值的踩坑。

### A. 运行中的 exe 不能直接改字节（error 32）

原计划「把配置追加到 exe 尾部」一步到位，实际一保存就报：

```
打开程序文件失败：另一个程序正在使用此文件，进程无法访问。 (os error 32)
```

Windows 把正在运行的镜像文件锁住了，`OpenOptions::write` 打不开。**但 exe 的 NTFS 数据流可以写**：

```rust
// 运行时保存：数据流，立即生效
C:\...\rdp-launcher.exe:rdp-launcher.cfg
```

数据流不改变 exe 字节，复制 exe 时资源管理器会带上（zip/部分下载工具会丢）。为了便携性，
正常退出时再派生一个 **临时 helper（本 exe 的副本）**，等主进程退出、exe 解锁后，把同一份
密文追加到 exe 字节尾部。启动时读两处，取 `revision` 更大的那份：

```text
运行时：数据流 revision N
正常退出：helper 写 exe 尾部 revision N
下次启动：两边都有 → 取 max(revision)
只有尾部（zip 解压/拷到 U 盘）→ 读尾部
只有数据流（运行中崩溃）→ 读数据流
```

数据流格式和尾部一样：`[AES-GCM 密文][u32 长度][16 字节 MAGIC]`。
helper 写完自己删不掉（正在运行），启动时清理一小时前的 `%TEMP%\rdp-launcher-embed-*.exe`。

### B. 这台机器不设 Mesa 环境变量会崩在 GL 初始化

现象：进程起来后第一帧画完就 `0xC0000005`，没有任何 Rust panic。用 `RDP_LAUNCHER_TRACE=1`
打日志才确认已经进 `update()`，是渲染阶段崩。手动加：

```powershell
$env:GALLIUM_DRIVER = "llvmpipe"
$env:LIBGL_ALWAYS_SOFTWARE = "1"
```

就正常。现在 exe 旁边只要有 `opengl32.dll` 或 `libgallium_wgl.dll`，程序在 `main()` 里
自动设置这两个变量，用户不用管。

### C. 弹窗必须「标题/按钮固定，中段滚动」

字段一多，原来整块 `ScrollArea` 会把「保存/取消」和删除确认顶到屏幕外（540 高窗口尤其明显）。
改成 `Modal → 标题 → ScrollArea(字段) → 错误条 → 底部按钮`，按钮永远可见。
删除确认展开时再按 `-142px` 缩 `body_h`，否则弹窗本身会高过屏幕。

### D. 分组和磁盘两栏并排

编辑弹窗按「基础字段 → 连接选项 → 分组 | 磁盘」排。`ui.columns(2, ...)` 左分组右磁盘，
把高度从 ~700 压到 ~560；声音/剪贴板不再被挤到滚动区域外面。

### E. 图标 / 版本信息 / DPI 用 rc.exe 嵌

没有引入 winres，`build.rs` 自己找 `rc.exe`（PATH → Windows Kits → 最新版本目录），
生成 `.res` 后 `cargo:rustc-link-arg=...res`。`build.ps1` 会把 SDK 的 `bin\x64` 加进 PATH。
`.rc` 路径统一用正斜杠，避免 rc 把反斜杠当转义。

### F. 同一 IP 不同端口的凭据限制（实测确认）

mstsc 的凭据 TargetName 是 `TERMSRV/<主机>`，**端口不参与**。所以同一 IP 上不同端口的两台机器
没法同时保存两套密码。连接本身完全支持（`full address` 带端口，`.rdp` 文件按主机 id 分开），
程序每次连接前重写凭据；编辑界面检测到「同地址不同端口 + 密码不同」会提示；删除时如果别的
主机共用同一 TargetName，不删凭据。

### G. 数据流和尾部要能互相兜底

`Store` 加了 `revision: u64`，每次保存 +1。启动时分别解密数据流和尾部，取 revision 大的；
一边坏了解不开就用另一边；两边都没有才走旧 JSON / 示例数据。旧 JSON 导入成功后删除。

### H. v3：新版 Windows 的 RDP 安全警告

Windows 2026 更新后，打开未签名、带剪贴板/磁盘重定向的 `.rdp` 会弹
「警告：未知的远程连接 / 发布者：未知发布者」，并把重定向默认取消。官方开关：

```text
HKLM\Software\Policies\Microsoft\Windows NT\Terminal Services\Client
    RedirectionWarningDialogVersion = 1
```

- 写 HKLM 必须管理员。程序启动时先写 HKCU `RdpLaunchConsentAccepted=1`（首次打开 .rdp 的同意，
  不需要管理员），再尝试写 HKLM（本身是管理员就静默成功）。
- 普通用户：顶部提示 / 设置 → Windows 兼容 → 按钮，`ShellExecuteW(..., "runas", "reg.exe", ...)`
  拉一次 UAC，用户点「是」后生效；主线程每 500ms 轮询 `is_suppressed()`，成功后隐藏提示。
- 不要写 HKCU 的 `RedirectionWarningDialogVersion`：那是机器策略，HKCU 写值可能和 IT 策略打架。
- 注意：不带 `/f` 的 reg add 在值已存在时会交互询问；命令里必须带 `/f`。
- **回退到 1 后还会弹旧版**：「无法识别此远程连接的发布者。是否仍要连接？」。
  这是 .rdp 未签名的发布者检查，mstsc 的「不再询问我是否连接到此计算机」复选框会写
  `HKCU\Software\Microsoft\Terminal Server Client\LocalDevices\<主机>` 的 bitflags。
  程序在启动/连接前写：
  - `AuthenticationLevelOverride=0`（HKCU，全局关闭服务器证书校验）
  - `LocalDevices\<主机>` 和 `LocalDevices\<主机:端口>` = `0x6F`（常用全允许位；资料里有写 4/8 的，
    0x6F 是合集）
  两个都不需要管理员。代价是证书校验被关掉，只适合信任的内网。
- 写 `LocalDevices` 的值名可以是 IP、域名、`host:port`；值名允许冒号，不允许反斜杠。主机地址已经
  在 `validate_host` 里挡掉了反斜杠。

### I. v3：托盘 / 关闭后保持后台

用 `tray-icon 0.24.2` + `muda 0.19`（tray-icon 自带 menu 再导出）。

- **托盘图标必须在事件循环所在线程创建**，Windows 上还要有 win32 消息循环。本程序在
  `hide_to_tray()`（主线程 `update` 内）懒创建，不在 `new()` 里。
- `MenuEvent` / `TrayIconEvent` 用 `set_event_handler`（tray-icon 推荐方式）：
  回调里把事件塞进 `Arc<Mutex<Vec<TrayMsg>>>` 并 `ctx.request_repaint()`。
  不要用后台线程 `receiver().recv()`：窗口隐藏后 `update()` 根本不跑，事件进了队列也没人排空。
- **最关键：不要用 `ViewportCommand::Visible(false)` 隐藏窗口**。Windows 对隐藏窗口不处理
  `RedrawRequested`，eframe 的 `update()` 就停了，表现是托盘图标能看见、右键菜单也能弹出，
  但「打开主界面 / 退出 / 快速连接」全部没反应。
  改成：**窗口最小化 + `ITaskbarList::DeleteTab` 去掉任务栏按钮**。
  最小化窗口仍会处理重绘，`update()` 继续跑；用户在任务栏只看到通知区域的小图标。
  还原时 `SW_RESTORE` + `ITaskbarList::AddTab` + `Focus`。
  另外隐藏期间每 250ms `request_repaint_after` 兜底，保证事件队列一定被排空。
- 托盘菜单：`Menu` / `MenuItem::with_id`；根级直接列**全部主机**（id `host:<id>`），
  再跟 `open` / `quit`。不要再套「最近主机」子菜单，少一次点击。
  菜单里的 `&` 会被当成快捷键标记，主机名里的 `&` 要转义成 `&&`。
- 托盘图标可能进 `∧` 溢出区；开发机断开的 RDP 会话里模拟 `PostMessage(hwnd, 6002, 0, WM_LBUTTONUP)`
  没有触发事件，因为 `get_tray_rect()` 对溢出图标拿不到矩形。正常桌面点图标没问题。
- 右下角版本号是 footer 里的透明按钮，点击打开关于弹窗（版本、说明、`QLing 制作`）。
- 托盘图标只在真正用到时创建；创建失败时不隐藏窗口，显示错误，避免用户找不回来。
- 真正退出必须走托盘菜单「退出」：先把 `self.tray = None` 移除图标，再发 `ViewportCommand::Close`，
  `on_exit` 照常 persist + helper。

### J. v0.3.3 输入/显示微调

- egui 自带的 `TextEdit::hint_text` 用 `weak_text_color()`，颜色跟正文 `override_text_color`
  走，在浅色主题下偏黑。改成不传 hint，`text_input()` 在空值时用 `Palette.hint`
  （浅色 `#B6BFCE` / 深色 `#666F7E`）自己画，裁剪在输入框 rect 内。
- 密码提示只在新主机显示：`HostForm.password_hint`，`new_add` 为 true，`from_host` 为 false。
  编辑已保存主机时即便密码为空也不再画「留空表示不保存密码」。
- 主机地址粘贴拆分：`split_host_port()` 处理 `host:port`、`域名:port`、`[IPv6]:port`；
  裸 IPv6（多个冒号）不拆。只在 **粘贴事件** 或 **失焦** 时拆，避免手动输入 `host:1`
  时第一位数就被拆走。
- 关于弹窗里的 `QLing 制作` 去掉 accent 底色/加粗，改成普通文本。

## 一、从零搭环境

原开发机是干净的 Windows 10 LTSC 19044，**Rust、MSVC、Windows SDK 全都没有**。

### 1. Rust

```powershell
# 走国内镜像，实测 8~9 MB/s（直连 crates.io 只有 0.1 MB/s）
$env:RUSTUP_DIST_SERVER = "https://rsproxy.cn"
$env:RUSTUP_UPDATE_ROOT  = "https://rsproxy.cn/rustup"
.\rustup-init.exe -y --default-toolchain stable-x86_64-pc-windows-msvc --profile default
```

约 34 秒装完。装出来是 Rust 1.100.0（eframe 0.31 要求 1.81+，够了）。

### 2. cargo 镜像

写 `%USERPROFILE%\.cargo\config.toml`：

```toml
[source.crates-io]
replace-with = "rsproxy-sparse"

[source.rsproxy-sparse]
registry = "sparse+https://rsproxy.cn/index/"

[net]
git-fetch-with-cli = true
retry = 5
```

项目里还有一份 `.cargo/config.toml` 兜底，换机器不配全局也能拉依赖。

### 3. MSVC + Windows SDK

装 VS Build Tools 2022，**只需要两个组件**：

```powershell
vs_buildtools.exe --quiet --wait --norestart --nocache `
  --installPath "C:\BT" `
  --add Microsoft.VisualStudio.Workload.VCTools `
  --add Microsoft.VisualStudio.Component.VC.Tools.x86.x64 `
  --add Microsoft.VisualStudio.Component.Windows11SDK.22621 `
```

装到 `C:\BT` 是为了短路径（避开 260 字符限制）。约 1.8 GB，25 分钟。

> 想更快就把最后一行删掉，只留 Workload VCTools + VC.Tools.x86.x64 + SDK 三项。


## 二、踩坑记录

### 坑 1：wgpu 对这台机器彻底不可用（最致命）

一开始因为原开发机是 RDP 会话（OpenGL 只有 1.1），把渲染后端从 glow 改成 wgpu，
结果启动直接：

```
Error: Wgpu(NoSuitableAdapterFound("request_adapters returned None"))
```

往下查了两层：

1. **wgpu-hal 主动拉黑整个 Intel Haswell 家族。** `auxil/dxgi/factory.rs` 的
   `should_keep_adapter` 里硬编码了一串 DeviceId，注释写着 Haswell 曾经支持 D3D12
   但后来因为安全漏洞被移除，所以干脆全部过滤。这块 HD 4400 的 DeviceId `0x0A16`
   就在名单里 —— 只要用 wgpu，这颗核显永远不会被选中。

2. **RDP 会话里 DXGI 枚举返回 0 个适配器。** 自己用 `CreateDXGIFactory1` + `EnumAdapters1`
   验证，第一个 adapter 就返回 `DXGI_ERROR_NOT_FOUND (0x887A0002)`。所以连 WARP
   软件适配器都拿不到，`native_adapter_selector` 里 `adapters` 是空数组。

**结论**：wgpu 在「Haswell 核显」或「RDP 会话」任一条件下都跑不了，两个条件这台机器全占。
最终回到需求原文指定的 **glow**。

### 坑 2：glow 在 RDP 会话里只有 OpenGL 1.1

```
GL_VERSION=1.1.0  GL_RENDERER=GDI Generic
```

原因是 RDP 会话不加载 Intel 的 OpenGL ICD（`ig75icd64.dll` 在磁盘上，但注册表
`HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\OpenGLDrivers` 是空的）。
egui_glow 要 GL 3.0+，1.1 直接 panic。

**解决**：用 Mesa 的 llvmpipe 软件渲染。从
[pal1000/mesa-dist-win](https://github.com/pal1000/mesa-dist-win) 下载
`mesa3d-26.3.0-release-msvc.7z`，取 `x64\opengl32.dll` + `x64\libgallium_wgl.dll`
放到 exe 旁边。`opengl32.dll` 不是 KnownDLL，应用目录优先于 System32，会被加载。

配合环境变量（可选，通常自动生效）：

```powershell
$env:GALLIUM_DRIVER = "llvmpipe"
$env:LIBGL_ALWAYS_SOFTWARE = "1"
```

代价是 CPU 渲染，界面慢一些但功能完整。**这是原开发机唯一能验证 UI 的方式。**

### 坑 3：`ui.available_width()` 在 ScrollArea 里返回 809.6，窗口只有 700

列表行的按钮全被画到窗口外，截图只能看到半个「编辑」。

```
[layout] avail=809.6 max_rect_w=809.6 rect=(14.0..823.6) clip=(0.0..700.0)
```

ScrollArea 把内容框算到了可视区之外。**修复**：不用 `available_width()`，改用
`clip_rect().right() - cursor().min.x - 18.0` 算实际宽度（见 `ui.rs` 的 `draw_host_row`）。

### 坑 4：mstsc 继承 stdio，把父进程的输出管道占死

`cargo test` 跑端到端测试时，mstsc 被拉起后测试进程卡住不退出，job 一直 running。

原因：`Command::spawn()` 不重定向 stdio，mstsc 继承了 test harness 的 stdout/stderr 句柄，
管道读端等不到 EOF。

**修复**：

```rust
std::process::Command::new(&mstsc)
    .arg(&rdp_path)
    .stdin(std::process::Stdio::null())
    .stdout(std::process::Stdio::null())
    .stderr(std::process::Stdio::null())
    .spawn()
```

GUI 程序没有控制台时看不出来，但只要从命令行或脚本启动就会暴露。

### 坑 5：VS 安装器走 Clash 代理，只有 0.04 MB/s

系统 WinINET 代理指向 `127.0.0.1:7890`，安装器老老实实走代理，实测 0.04 MB/s，
1.8 GB 要装 12 小时。

**解决**：给 `HKCU\...\Internet Settings\ProxyOverride` 追加微软域名直连，
不改全局代理设置：

```
*.microsoft.com;*.visualstudio.microsoft.com;*.windowsupdate.com;*.azureedge.net;aka.ms
```

改完立刻生效（`InternetSetOption` 刷一下）。装完记得还原。

### 坑 6：egui 0.31 的 API 和旧版本对不上

| 旧写法 | 0.31 正确写法 |
|---|---|
| `Frame::none()` | `Frame::new()` |
| `Button::rounding()` | `Button::corner_radius()` |
| `Margin::same(14)` 传 i32 | 参数是 **i8**，`Margin::same(14i8)` |
| `CornerRadius::same(8)` 传 f32 | 参数是 **u8** |
| `WgpuConfiguration.supported_backends` | 没有这字段，在 `WgpuSetup::CreateNew.instance_descriptor.backends` |
| `Context::frame_nr()` | **不存在**，自己数帧 |
| `Window` 做模态 | 用 0.31 新增的 `egui::Modal`（自带遮罩并挡点击） |

### 坑 7：`CredWriteW` 的 `CREDENTIALW.Flags` 是 `CRED_FLAGS` 不是整数

```rust
cred.Flags = 0;              // E0308: expected `CRED_FLAGS`, found integer
cred.Flags = CRED_FLAGS(0);  // ✅
```

### 坑 8：`Path::new(&format!(...))` 临时值生命周期

```rust
let probe = Path::new(&format!("{letter}:\\"));  // E0716: temporary dropped while borrowed
```

`Path` 借用了临时 `String`，语句结束就悬空。改成先绑定：

```rust
let probe_root = format!("{letter}:\\");
let probe = Path::new(&probe_root);
```

### 坑 9：`Stroke::new(1.0, ...)` 触发 f64→f32 推断警告

`Stroke::new` 的宽度参数是 `impl Into<f32>`，字面量 `1.0` 默认是 f64，编译器会
fallback 到 f32 并警告。写 `1.0_f32` 干净。

### 坑 10：弹窗内容超出 540 高地窗口

第一版弹窗用「标签一行 + 输入框一行」的竖排，总高 700+，锚点居中导致顶部和底部
都被切到屏幕外。

**修复**：两列 `egui::Grid`（左标签固定 64px，右输入框占满），总高压到 ~370。
窗口只有 540 高时，弹窗必须按「行」而不是「块」排。

## 三、架构要点

### 冷启动顺序

```
读 exe 数据流 / 尾部配置 → 装字体 → 画第一帧 → （第二帧）启动探活线程池
```

探活放到第二帧之后，是为了让窗口先出现在屏幕上，不被 DNS 解析和
800ms 超时拖住。

### 探活线程池

`probe.rs` 里用 `Arc<Mutex<Vec<Task>>>` 做任务队列，起 `min(32, 主机数)` 个线程抢任务。
每个 worker 退出时 `tx` 的克隆被释放，全部退出后接收端拿到 `Disconnected`，
据此判断「全部测完」—— 不需要额外的完成信号。

### 凭据写入

```rust
let target = parsed.cred_target();   // "TERMSRV/192.168.1.10"，端口已剥
let mut blob = password.encode_utf16().flat_map(|u| u.to_le_bytes()).collect();
// CREDENTIALW: Type=CRED_TYPE_GENERIC, Persist=CRED_PERSIST_LOCAL_MACHINE
CredWriteW(&cred, 0)
```

密码必须以 **UTF-16 LE 字节**写入 `CredentialBlob`，长度是字节数（不含 NUL）。

### 键盘拦截优先级

在 `update()` 最开头、任何 widget 绘制之前 `consume_key`：

```rust
if self.form.is_some() || self.delete_confirm.is_some() {
    // 弹窗打开：只拦 Esc
    return;
}
ctx.input_mut(|i| i.consume_key(Modifiers::NONE, Key::ArrowDown));
// ... ArrowUp / Enter / Esc
```

不这么做的话，聚焦的 `TextEdit` 会吃掉方向键，`Esc` 只失焦不清空文本。

## 四、调试手段

| 环境变量 | 作用 |
|---|---|
| `RDP_LAUNCHER_OPEN_DIALOG=add\|edit\|delete\|settings\|toast` | 启动直接弹对应窗口，用于截图验证 |
| `RDP_LAUNCHER_VIEW=grid\|list` | 指定显示方式启动 |
| `RDP_LAUNCHER_CLOSE_TO_TRAY=1` | 强制开启「关闭后保持后台」，测试托盘 |
| `RDP_LAUNCHER_HIDE_WARNING_HINT=1` | 隐藏 RDP 安全警告顶部提示（截图用） |
| `RDP_LAUNCHER_TRACE=1` | 启动阶段写 `%TEMP%\rdp_launcher_startup.log` |

## 五、已知限制

1. **纯 RDP 会话里必须放 Mesa dll**，否则 glow 起不来；放好后程序自动设 llvmpipe 变量。
2. **数据流需要 NTFS**。FAT32/exFAT 保存会报错（常驻红条），不会静默丢数据。
3. **最新数据在正常退出后才写进 exe 字节**。运行中直接 zip 只带上次退出时的数据；
   数据流仍是最新的，下次在本机启动可恢复。
4. **同一 IP 不同端口的凭据共享 `TERMSRV/<主机>`**，是 Windows 的限制；连接本身支持。
5. **这台开发机没有 D 盘**，盘符拼接只验了 C 和缺失盘符的降级路径，其余盘靠单测覆盖。
6. **没有真实可连的 RDP 目标机**，端到端测试只验证到「写凭据 + 生成 rdp + 拉起 mstsc」。
7. 未做多实例互斥；同时开两个窗口会互相覆盖最后保存的那份。
8. 只做了 IPv4/域名/IPv6 的解析，没做 DNS 预解析缓存。
